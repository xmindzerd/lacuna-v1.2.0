# 导演剧本分析

每次交付一份可编辑的本地 Excel，只含一张 `Scene by Scene` 工作表，一场一行。默认分析所给剧本的全部正文；用户指定集数、场次或片段时按指定范围交付。聊天中给出文件链接、范围和必要的原稿疑点。

## 读本

1. 识别当前剧本版本。先读完整的所给材料，再从正文按出现顺序列出场头。简介、大纲、人物小传作背景；正文决定每场实际发生什么。中英对照只算一次。文档里的表格、文本框或扫描页有正文时一并读取；有缺页影响覆盖时明确说明。
2. 一场一行。保留原场号和顺序，重复场号以场景名、时空和行序区分；已有导演定稿明确给了 A/B 时沿用。场内回忆、监控、电话、平行剪辑随原稿归属。无集号或场号的原稿允许对应格留空。无场头时按明确的时空切换分场，并在交付消息告知。
3. 先逐集判断开头怎么接、冲突在哪一拍达到高潮、结尾实际停在哪个动作，以及观众还想追什么。已有导演分集阐述时，用它校准节拍和视觉重点，再回正文找对应场次。顺着重要关系检查谁知道真相、谁误读、哪一拍才揭晓。查上一场留下的物品、衣着、伤妆、人物位置和情绪，再写下一场。原稿矛盾保留其原意，影响拍摄的疑点在交付消息点明。

## 写表

填写前必须读 [四份 Director List 的十条规则及逐场案例](references/directing.md) 和 [必需镜头的判断规则](references/required-shots.md)。先找每集的看点，再写能发挥的拍法与分镜必须落实的镜头。第1集开头必须有具体抓眼设计，第2–10集根据剧情强化重点。前十一列如下。

| 列 | 写什么 |
|---|---|
| 集、场次、场景 | 从原场头提取。场景保留地点、日夜、内外及原有时空标记。 |
| 剧情核心（分集节拍／本场） | 每行写清本场造成的变化。把【开头】【高潮】【结尾】【钩子】分别写在实际承载该节拍的场次，同格分行。结尾写最后看见或听见什么，钩子写此刻仍悬着的具体期待。普通承接场只写本场作用。 |
| 视觉重点 | 给分镜创作方向：指出哪一拍值得加密、跟谁看、哪种运动或视角变化能强化它。由分镜根据空间与节奏选择拍法。 |
| 必需镜头 | 分镜必须逐项落实。点名主体、动作时点和必看的结果，分行写清特写、脸部反应、不同角度、慢动作范围或运镜落点。群戏重要时刻须写在场主角、关键配角及群演的不同反应。普通承接场可空。 |
| 情绪重点 | 具体到人物、触发点和反应。有些过场只有一个简单的情绪动作，照实写。 |
| 服装 | 重点写造型的首次建立、换装、破损和接戏，或服装如何服务表演。 |
| 场景氛围要求 | 用具体光源、声音、视线、距离或人群反应表达这场戏的感受。 |
| Key Prop | 列出承担识别、误导、反转、行动或接戏的关键道具，必要时写清归属和状态。 |
| 特殊要求说明 | 仅写已有的明确要求或原稿成立所需的执行条件，如电话另一端只出声、证物内容须可辨认。 |

同一集只有一场时，四个节拍都放在该行；高潮和结尾重合可合写【高潮／结尾】。终集已经收束可写【钩子】全剧收束及落点。只给片段时，只标原稿能确认的节拍，别把片段末尾当整集结尾。不要为单集分析增设总览页、汇总行或逐镜清单。

末列「导演问题/说明」专供团队手填，所有数据行保持真正空白。可选栏目没有内容时同样留空。说明性内容以中文写，原稿中重要的外文人名、招牌及道具文字可原样保留。区分原稿事实和导演处理，未交代的情节不可补成事实。篇幅优先给真正改变戏的那一拍。

## 导出

在临时目录准备 UTF-8 JSON：`{"title":"剧名｜第1–3集 导演剧本分析","rows":[...]}`。每行是按上述顺序排列的十一个字段，空白用空字符串表示。更新旧稿时，按场次在视觉重点后插入必需镜头。集号也可以是数字。把原场号当文本写，例如 `1-1`。

用工作区依赖工具取得 Node.js 路径，以该 Node 运行本 skill 目录内的 `scripts/export.mjs 输入.json 输出.xlsx`。默认使用与该 Node 并列安装的 artifact-tool；运行库另行提供时可设置 `DIRECTOR_NODE_MODULES` 为其 node_modules 目录。输出文件选用剧名与范围命名。脚本自动生成团队栏、工作表样式和行高，保护已有同名文件。重交时使用新版本名。

在 ChatGPT 中，若环境缺少上述 Node 运行库，使用数据分析环境已有的 Excel 写入库生成同规格 .xlsx：单页 Scene by Scene、相同 12 列顺序、原场号为文本、团队栏全空、自动换行、按最长内容调整行高并冻结标题与表头。保存到可下载的输出目录，并在回复中链接该文件。

逐集检查开头、高潮、结尾和钩子能否在相应行直接读到。逐场核对导出顺序、总数、揭晓时机和连续性。检查必需镜头每一条能否在下游对应到实际镜号；同一节拍需要独立角度的，分别写清。打开成品或渲染最长的几行，确认场号为文本、总共 12 列、团队栏无值或公式、文字可读。只交付最终 .xlsx，不把工作用的 JSON 一起交付。
